A ideia em uma frase

O Claude agora lê só o pedaço do repositório que a tarefa toca, e toda mudança de regra atualiza o documento dela no mesmo commit. Esse hábito é a micro memória: o repositório lembra por você.

Quem o Claude lê, e quando

A documentação foi cortada em camadas. Cada camada só entra no contexto quando a tarefa precisa dela, e nenhuma repete a outra.

02

A micro memória, passo a passo

Documentação morre quando atualizar é uma tarefa separada. A micro memória junta as duas coisas: quem muda a regra escreve a nota da regra, no mesmo commit. É pequena (uma linha, um prazo, uma guarda) e nasce junto do código que ela descreve.

O que conta como "a regra mudou"

Atualiza o documento
  • transição de estado nova
  • guarda nova ou removida
  • prazo, default ou flag alterados
  • campo que vira obrigatório, permissão nova
Não atualiza
  • refactor sem mudar comportamento
  • renomear função ou arquivo
  • teste novo
  • ajuste de texto de tela

Um exemplo concreto

Você pede: "a janela de disputa depois da conclusão passa de 48 h para 72 h". O Claude muda a migration e lib/actions/disputes.ts. O docs-sync.json diz que esse arquivo é cobrado por docs/dominio/disputas.md, então a linha "até completed_at + 48 h" vira 72 h no mesmo commit. Se ele esquecer, o diagnosticar.py do fecho acusa drift e o PR não fecha limpo.

Duas regras que evitam bagunça

Atualizar não pergunta, criar pergunta. Documento que já existe é obrigação da Task. Área nova ou CLAUDE.md novo passa pelo seu OK no fecho do PBI.

Documento diferente do código é defeito, não documento velho. Se divergir do CONTEXT.md, a divergência vai para você decidir; o Claude não escolhe um lado em silêncio.

03

O que mudou na prática

Antes
  • sessão lia 240 KB ou adivinhava a regra
  • tela nova copiava cor do arquivo mais próximo
  • documento atualizado "depois", ou nunca
  • rota nova sem saber qual guarda usar
Depois
  • lê o AGENTS.md e só a área da tarefa
  • copia o molde certo: EnderecoInicial para formulário, RentalCenterEmptyState para vazio
  • documento muda no commit da regra
  • app/CLAUDE.md diz a guarda de cada grupo de rota

Cores: medido, não opinado

O código tem duas gerações de cor: tokens da marca (text-ink, border-hair) e um legado com a paleta cinza do Tailwind escrita em hex. O PR 29 ligou 74 cores ao token sem mudar um pixel, só onde o valor era idêntico.

Os 314 que sobraram mudariam a cor na tela se virassem token: #111111 não é o --ink (#1d1d1f). Alinhar esse legado é decisão de marca, sua, com a tela aberta.

A armadilha

O plugin dent2dent cobra a documentação no fecho do PBI, pelo diagnosticar.py. Numa conversa avulsa, fora das fases, ninguém cobra sozinho: a regra do AGENTS.md pede, mas só o gate confere. Antes de abrir PR feito fora das fases, peça a conferência.
